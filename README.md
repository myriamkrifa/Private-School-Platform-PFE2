# Private School Management Platform

A full-stack school management platform for private schools. Provides four
role-based experiences (Admin, Teacher, Parent, Student) covering users,
classes, academic years, subjects, teaching assignments, grades, attendance,
assignments, course materials, announcements, parent–teacher messaging,
notifications, and audit logging.

## Tech stack

- **Frontend**: React 18, JavaScript ES6+, Vite, Tailwind CSS, custom CSS, Recharts, jsPDF, lucide-react
- **Backend**: Node.js, Express.js, REST API, JWT authentication, bcryptjs
- **Database**: MySQL (Prisma provider = `mysql`)
- **ORM**: Prisma 6
- **Tooling**: Git, Postman, Vite, Nodemon

## Features by role

### Admin
- Dashboard with stats: students, teachers, parents, classes, subjects, today's absences, active academic year, recent announcements, recent activity (audit logs).
- Manage users, students, teachers, parents (provision accounts with autogenerated credentials).
- Manage academic years (create / activate / update).
- Manage classes (CRUD, add/remove students, add/remove teachers, see capacity).
- Manage subjects (CRUD with code, coefficient, level).
- Manage teaching assignments (teacher × class × subject, with delete).
- Reports: per-class, per-student, teacher workload, CSV export.
- Publish announcements targeted to a role and/or class.
- Audit log of important actions.

### Teacher
- Dashboard with assigned classes, subjects, today's attendance taken, recent grades, recent assignments, parent messages.
- Enter grades by class + subject (0–20 bulk input with type/title/date).
- Mark attendance per class/subject/date (PRESENT / ABSENT / LATE / EXCUSED) with justification.
- Create assignments for full class or selected students.
- Publish course materials (text content or external URL).
- Receive messages from parents, reply.

### Parent
- Dashboard with linked children, latest grades, recent absences/lates, announcements, unread notifications, teacher messages.
- View per-child grades, attendance history, and assignments.
- View announcements targeted to PARENT or to the child's class.
- Send messages to the child's teachers; receive notifications.

### Student
- Dashboard with class/room/level, recent grades, attendance summary, upcoming assignments, course materials, announcements.
- Read-only views of grades, attendance, assignments, course materials, announcements.
- Optional assignment submissions (text + URL).

## Database schema (highlights)

| Model | Notes |
|------|-------|
| `User` | id, name, email, password, role (`ADMIN`/`TEACHER`/`PARENT`/`STUDENT`), `isActive`, `identityCardNumber`, `phoneNumber`. |
| `Student` | linked to a `User` (1-1) and a `Class` (1-N). Fields: name, grade, status, enrollmentDate, … |
| `Teacher` | linked to a `User` (1-1). Fields: subject, specialty, status. |
| `ParentStudent` | many-to-many bridge between Parent users and Students. |
| `AcademicYear` | name, startDate, endDate, isActive. |
| `Class` | name, room, level (`PRIMARY`/`SECONDARY`), capacity, academic year, students, teachers (M-N), teaching assignments. |
| `Course` | acts as **Subject**: title, code, coefficient, optional levelTag. |
| `TeachingAssignment` | unique `(teacherId, classId, courseId)` — defines who can grade/take attendance for what. |
| `Grade` | studentId, classId, courseId, teacherId, score (0–20), maxScore (20), `type` (TEST/EXAM/HOMEWORK/ORAL/PROJECT), title, comments, recordedAt. |
| `Attendance` | unique `(studentId, classId, courseId, date)`, `status` enum, `justification`, recorded by takenBy. |
| `Assignment` + `AssignmentRecipient` + `Submission` | full-class or per-student assignments with optional submissions. |
| `CourseMaterial` | per-subject material (title, description, content, fileUrl). |
| `Announcement` | optional `targetRole` and/or `classId`. |
| `Message` | senderId, recipientId, subject, content, isRead. |
| `Notification` | per-user, with type enum, isRead. |
| `AuditLog` | actorId, action, entityType, entityId, before/after/metadata as JSON. |

## Setup

### 1. Prerequisites
- Node.js 18+
- A running MySQL 8 server (or MariaDB 10.5+).
- Create an empty database, e.g.:

```sql
CREATE DATABASE private_school_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 2. Backend

```bash
cd backend
cp .env.example .env       # then edit DATABASE_URL / JWT_SECRET
npm install
npx prisma generate
npx prisma db push         # applies the schema to MySQL (no migration files needed)
npx prisma db seed         # loads demo accounts + sample data
npm run dev                # http://localhost:5000
```

Expected `.env`:

```
PORT=5000
JWT_SECRET=replace_with_a_strong_secret_key
CLIENT_URL=http://localhost:5173
DATABASE_URL="mysql://root:password@localhost:3306/private_school_db"
```

### 3. Frontend

```bash
cd frontend
npm install
npm run dev                # http://localhost:5173
```

If the API runs on a different host/port, set `VITE_API_URL` (e.g. in
`frontend/.env`):

```
VITE_API_URL=http://localhost:5000/api
```

## API overview (selected)

Auth (`/api/auth`):
- `POST /login`, `POST /logout`, `GET /me`, `POST /register` (admin-only)

Dashboards:
- `GET /api/admin/dashboard`
- `GET /api/teacher/dashboard`
- `GET /api/parent/dashboard`
- `GET /api/student/dashboard`

Reports:
- `GET /api/reports/class/:classId`
- `GET /api/reports/class/:classId/export` (CSV)
- `GET /api/reports/student/:studentId`
- `GET /api/reports/teacher-workload`

Resources:
- Users: `GET /api/users`, `POST /api/users/provision/student`, `POST /api/users/provision/teacher`, `PATCH /api/users/:id/role`
- Students: `GET/POST/DELETE /api/students`, `GET /api/students/:id`, `GET /api/students/me/children`, `POST /api/students/:id/parents`, `GET /api/students/:id/progress`
- Teachers: `GET/POST/DELETE /api/teachers`, `GET /api/teachers/:id`
- Classes: `GET/POST/PUT/DELETE /api/classes`, `GET /api/classes/:id`, `POST /api/classes/:id/students`, `DELETE /api/classes/:id/students/:studentId`, `POST /api/classes/:id/teachers`, `DELETE /api/classes/:id/teachers/:teacherId`
- Academic years: `GET/POST/PATCH/DELETE /api/academic-years`, `PATCH /api/academic-years/:id` (set `isActive: true` to activate)
- Subjects: `GET/POST/PUT/DELETE /api/subjects`, `GET /api/subjects/:id`
- Teaching assignments: `GET/POST/DELETE /api/teaching-assignments`
- Teacher workspace: `GET /api/teacher/classes`, `GET /api/teacher/classes/:classId/students`, `GET /api/teacher/classes/:classId/subjects`
- Grades: `POST /api/grades`, `POST /api/grades/bulk-upsert`, `GET /api/grades/student/:studentId`, `GET /api/grades/student/:studentId/average`, `GET /api/grades/student/:studentId/export` (CSV), `GET /api/grades/class/:classId/average`
- Attendance: `POST /api/attendance`, `POST /api/attendance/bulk-upsert`, `GET /api/attendance/student/:studentId`, `PATCH /api/attendance/:id/justify`
- Assignments: `POST /api/assignments`, `GET /api/assignments/course/:courseId`, `POST /api/assignments/:id/submissions`, `GET /api/assignments/:id/submissions`
- Courses & materials: `GET/POST /api/courses`, `GET /api/courses/materials`, `GET /api/courses/:courseId/materials`, `POST /api/courses/:courseId/materials`, `DELETE /api/courses/materials/:id`
- Announcements: `GET/POST /api/announcements`
- Messages: `GET /api/messages`, `GET /api/messages/inbox`, `GET /api/messages/sent`, `GET /api/messages/contacts`, `POST /api/messages`, `PATCH /api/messages/:id/read`
- Notifications: `GET /api/notifications/me`, `PATCH /api/notifications/:id/read`, `PATCH /api/notifications/me/read-all`
- Audit: `GET /api/audit?limit=100`

A Postman collection is provided in `docs/postman_collection.json` and a
detailed walkthrough in [docs/API.md](docs/API.md).

## Business rules enforced server-side

1. A student belongs to one class at a time (`Student.classId` is single-valued).
2. Classes belong to one level and one academic year.
3. Teachers can only grade or mark attendance for `(class × subject)` pairs they
   have a `TeachingAssignment` for.
4. Parents only see their own children (validated via `ParentStudent`).
5. Students only see their own data.
6. Grades must be in `[0, 20]`.
7. Attendance status must be `PRESENT`, `ABSENT`, `LATE`, or `EXCUSED`.
8. Announcements may target everyone, a role, or a class.
9. Notifications are emitted for grades, absences/lates, announcements, new
   assignments, and new messages.
10. Audit log records grade/attendance/announcement/teaching assignment changes.

## Known limitations

- File uploads are simulated via `fileUrl` on materials/submissions; no binary
  storage is implemented (per requirements).
- Reports export to CSV; PDF report cards rely on the in-app jsPDF generator
  on the dashboard.
- "Levels" are represented by the `ClassLevel` enum (`PRIMARY` / `SECONDARY`);
  no separate Level table is required by the current schema.
- Rate limiting and refresh tokens are not implemented (JWT is short-lived
  but issued without a refresh token).
